# 任务2全量自训练实验方案书

**方案日期：2026-07-23**
**实验ID：`task2_diotic_full_20260723_seed20260721`**

## 1. 任务来源与定位

2026年7月21日会议确定的研究顺序是：

1. 先用作者公开的训练完成模型检查双耳分离任务；
2. 然后尝试自己训练模型；
3. 获得训练过程中的模型状态后，再研究选择性听取能力如何随训练发展；
4. 最终考虑与人的发达数据进行趋势比较。

因此，本方案对应会议中的任务2，即“从随机权重自己训练模型”。它不是前两个
checkpoint复现实验的重复，也不是继续微调作者checkpoint。

## 2. 研究问题

主要问题：

> feature-gain选择性听取机制，能否仅通过自己的Common Voice语音混合训练，从随机
> 初始化中形成？

次要问题：

1. 自训练模型能否形成随SNR升高而提高的目标词正确率？
2. 是否出现“异性干扰比同性干扰容易”的趋势？
3. 是否出现随干扰说话人数增加而变难的趋势？
4. 不同训练阶段的模型是否表现出有序的能力变化？
5. 这种变化与人的发达数据是否在方向上相似？

第五项只能比较轨迹或条件效应，不能直接把“1个epoch”等同于“某个年龄”。

## 3. 本轮“全量”的准确含义

### 3.1 本轮包含

- Common Voice v9 English；
- 固定800词分类任务；
- 从随机权重开始；
- 一个feature-gain架构；
- cue与target来自同一说话人，但来自不同录音和不同锚点词；
- 1–4名不同的语音干扰说话人；
- diotic输入，即左右声道完全相同；
- SNR在−10～+10 dB在线采样；
- 10% cue-free样本；
- 目标性别和目标词尽量平衡；
- 最多500,000条在线样本/epoch、10 epoch；
- 单张HAKUSAN A100训练。

### 3.2 本轮不包含

- 论文的房间模拟与KEMAR HRTF；
- BRIR残响空间化；
- AudioSet非语音干扰；
- 13个架构训练与top-10模型平均；
- 论文约397万条原始场景的逐条重建。

因此，最终报告应使用：

> `diotic-trained, speech-only, single-architecture model`

不能使用：

> “完整复现了原论文的训练模型”

### 3.3 与最终双耳研究的关系

diotic训练可以回答非空间条件下feature-gain是否形成，并可直接评测性别条件和多话者
条件。但是，diotic训练从未提供左右耳不同的学习信号，不能单独证明模型学会了双耳
分离。

如果最终目标必须解释双耳分听的发达过程，完成本轮后还需要任务2B：

- 增加左右耳不同的训练样本，或
- 重建包含HRTF/BRIR的空间化训练。

本轮是可执行的第一阶段，不是整个发达研究的终点。

## 4. 数据设计

### 4.1 数据划分

- 训练来源：Common Voice v9 English train；
- 验证来源：Common Voice v9 English dev + test。最初只使用dev，但两轮HAKUSAN
  对齐后dev-only可配对覆盖停在681/800且候选耗尽，因此于2026-07-26显式加入
  官方test以维持至少700词的既定门槛；
- 排除两个复现实验与双耳评测中使用过的说话人；
- train、validation和evaluation说话人必须完全不重叠；
- 固定词表为`cv_800_word_label_to_int_dict.pkl`。

说话人分离优先于样本数量。任何重叠都必须停止训练并重新生成划分。

### 4.2 锚点目录

对音频进行MMS强制对齐，保留能够以目标词中心截取2.5秒的锚点。一个说话人只有在
至少拥有两个不同录音和两个不同词时，才可用于cue/target配对。

正式启动门槛：

| 检查项 | 门槛 |
|---|---:|
| pairable训练词 | 800/800 |
| pairable验证词 | 至少700/800 |
| train–validation说话人重叠 | 0 |
| train–evaluation说话人重叠 | 0 |
| validation–evaluation说话人重叠 | 0 |

截至2026-07-23，训练为54/800词、验证为17/800词，尚未达到门槛。

2026-07-26更新：训练已达到800/800；dev-only验证达到681/800后耗尽可配对候选。
dev+test新验证候选共4,510条、2,270名说话人，泄漏检查仍全部通过，等待新增test
音频对齐后重新评估700词门槛。

### 4.3 在线样本生成

每条训练样本的构造：

```text
target = 目标说话人的目标词中心2.5秒
cue = 同一目标说话人、不同录音、不同锚点词的2.5秒
distractors = 1至4名不同于目标说话人的语音片段
background = 各干扰语音等RMS后求和
input = 按随机SNR混合target与background
channel = 左声道等于右声道
label = target中央词的800类标签
```

cue-free样本占10%，此时cue和background为静音，只保留target。

## 6. 正式实验阶段

### 阶段A：扩大强制对齐目录

在HAKUSAN重复提交可恢复的对齐作业。每次完成的clip都会写入JSONL，再次提交时自动
跳过。

结束条件不是“作业跑完一次”，而是readiness达到800/700且说话人重叠为0。

### 阶段B：数据与GPU预检

必须依次通过：

1. `check_readiness --require-all-words`；
2. `check_dataset`；
3. HAKUSAN GPU上的随机初始化smoke training；
4. batch=32、16-mixed的显存与吞吐测试；
5. 估算500,000条样本是否能在24小时作业限制内完成一个epoch。

如果单个epoch预计超过约20小时，不直接启动正式作业。应把每个epoch的样本数缩小，
同时相应增加epoch数，使总训练样本量基本不变，并确保每个作业结束前能保存checkpoint。

### 阶段C：实现发达分析所需checkpoint策略

当前训练器只保证best和last checkpoint，无法完整分析训练轨迹。正式全量前必须：

- 保存随机初始化的stage 0；
- 至少每个epoch保留一个checkpoint；
- 保留best和last；
- 记录每个checkpoint对应的epoch、global step和累计训练样本数。

按照当前10 epoch设计，预计保存stage 0、epoch 1–10、best和last。现有smoke checkpoint
约700 MB/个，因此应预留至少10 GB，正式运行前以HAKUSAN实际文件大小复核。

### 阶段D：正式训练

只有A、B、C全部通过后才提交正式作业。中断时只从本项目自己的last checkpoint恢复，
不能加载作者checkpoint。

每次作业记录：

- Git commit；
- config SHA256；
- Slurm job ID；
- GPU型号和显存；
- 开始与结束时间；
- 是否从checkpoint恢复；
- train loss、val loss、val accuracy；
- 最后保存的epoch与global step。

### 阶段E：评测

对随机初始化、若干中间epoch、best和last使用同一套冻结评测刺激。

最低评测矩阵：

| 评测 | 目的 |
|---|---|
| cue-free/clean 800词 | 确认基本词识别是否学会 |
| 实验1：同性/异性×SNR | 检查性别分离趋势 |
| 实验2：1/2/4/8 talker×SNR | 检查说话人数效应 |
| 双耳任务1 | 探索性检查；diotic训练不保证成功 |

所有阶段使用同一批评测刺激、同一评分代码和同一随机种子，避免把刺激变化误认为发达
变化。

## 7. 成功标准

### 7.1 工程成功

- readiness全部通过；
- 训练无NaN/Inf；
- checkpoint可恢复，恢复后global step连续；
- 训练与验证loss总体下降；
- best、last和阶段checkpoint均可独立载入；
- 运行记录可以重建完整命令。

### 7.2 模型最低成功

- clean/cue-free正确率显著高于1/800随机水平；
- SNR升高时目标词正确率总体提高；
- 训练后模型优于stage 0；
- 不同训练阶段形成可解释而非完全随机的变化。

### 7.3 研究性成功

至少出现一项稳定的选择性听取效应：

- 异性干扰条件优于同性干扰条件；
- 干扰人数变化产生系统性差异；
- feature-gain启用与控制条件之间出现稳定差异。

绝对正确率不必等于作者模型。若没有出现上述效应，也应作为结果报告，因为它说明
diotic语音训练可能不足以形成论文中的机制。

## 8. 风险与应对

| 风险 | 处理 |
|---|---|
| 稀有词始终无法达到800词 | 输出缺失词表，增加对齐clip；必要时讨论降低门槛，但不能静默更改 |
| A100 OOM | 降低batch并提高梯度累积，保持有效batch接近64 |
| 单epoch超过作业时限 | 缩短epoch、增加epoch数；先保证可保存和恢复 |
| HAKUSAN中断 | 使用last checkpoint和`RESUME=1` |
| checkpoint空间不足 | 只保留预定阶段、best、last；先核对配额 |
| 训练学不会800词 | 检查词频、性别平衡、cue/target配对和学习率 |
| 双耳任务表现差 | 视为diotic训练边界，进入任务2B而非强行解释 |
| 与人的数据不一致 | 先确认模型测量可靠，再比较条件趋势，不直接映射年龄 |
