## 2. 本地审计首先发现的问题

### 2.1 Numerics preflight 与正式配置不一致

当时的 `full.yaml` 已使用：

```text
accumulate_grad_batches = 9
```

但 `run_numerics_preflight.sbatch` 仍硬编码要求 accumulation=2，并假设：

```text
6,000 microbatches / accumulation 2 = 3,000 optimizer attempts
```

若直接使用新配置，预飞会在 GPU 训练前因 assertion 失败；即使只把 2 改成 9，6,000 microbatches 也只有约 667 attempts，无法覆盖原定 3,000-attempt 数值安全门槛。

### 2.2 `last.ckpt` 与 `last-v1.ckpt` 恢复断链

提交端固定对 `last.ckpt` 计算 SHA，但运行端会按 mtime 重新选择最新 `last*.ckpt`。在 Job 529550 已经出现：

```text
last.ckpt     = 旧父状态
last-v1.ckpt  = 新最终状态
```

这会造成两种风险：

- 提交端锁旧文件，运行端选新文件，启动后 hash mismatch；
- 为避免 mismatch 而固定回 `last.ckpt`，又可能静默回退到旧训练状态。

### 2.3 现有 COMPLETE 运行不能直接换配方续训

旧运行已经写入 `COMPLETE`，现有 wrapper 会拒绝普通 resume/fork；同时 `epochs`、accumulation 等配置已改变，旧 snapshot/PASS 也不能合法复用。因此不能把修改后的配方直接接在旧目录继续。

### 2.4 Cue smoke 不能直接放行 full

32 条 smoke 只能证明：

- checkpoint 可加载；
- manifest/evaluator 能运行；
- 两次推理可重复；
- 输出格式和哈希链正常。

它不能证明 10,000 条正式对照达到科学门槛，所以需要独立 release checker，不能“默认成功”。

### 2.5 四轮 pilot 缺少冻结评价证据

内置 training metrics 只有 aggregate validation 指标，没有保存：

- distractor count；
- 实际 SNR bin；
- mixed 与当前 `cue_free`/clean 样本的区分；
- stage-0 与 pilot-final 在同一 scene 上的逐 trial 配对预测。

如果先看到 4 轮结果再设计 evaluator，会引入看结果后改判据的分析自由度，也会改变 snapshot provenance。

## 3. 实际完成的代码修改

## 3.1 正式训练样本与 accumulation 对齐

将正式每轮样本数从 500,000 调整为：

```text
499,968 = batch 32 × accumulation 9 × 1,736 optimizer attempts
```

这样每轮所有 optimizer attempts 都由完整的 9 个 microbatches 构成，不再出现最后一次只有 1 个 microbatch 的 partial accumulation。

对应预算：

- 4 轮 pilot：1,999,872 个在线场景、6,944 attempts；
- 40 轮总上限：19,998,720 个在线场景、69,440 attempts。

涉及：

- `selftrain/configs/full.yaml`
- `selftrain/scripts/check_training_phase.py`

## 3.2 重做 accumulation=9 数值预飞

新的预飞保持原先 3,000 次 optimizer-attempt 覆盖，而不是削弱安全检查：

```text
864,000 examples
27,000 microbatches
batch size 32
accumulation 9
effective batch 288
3,000 optimizer attempts
16 小时 walltime
```

PASS schema 升为 3，并检查 examples、microbatches、batch、accumulation、effective batch、attempts、global step 和 AMP accounting 的算术一致性。旧 PASS 会因 semantic digest/schema 不符而被拒绝。

涉及：

- `selftrain/hakusan/run_numerics_preflight.sbatch`
- `selftrain/scripts/run_integrity.py`
- `selftrain/scripts/test_run_integrity.py`

## 3.3 修复 checkpoint 精确引用

新增 checkpoint reference 机制：提交时一次性确定并锁定：

```text
basename + SHA256 + global_step + resume kind
```

计算节点只打开这一个明确文件，不再自行 glob/mtime 重选。额外拒绝：

- 路径穿越；
- symlink；
- 非法 basename；
- rolling/epoch kind 错配；
- 提交后内容变化；
- global step 与记录不一致。

`fork-resume` 也允许显式读取父运行的 `last-vN.ckpt`，然后在子运行中写入 canonical `last.ckpt`，并保留 lineage。

涉及：

- `selftrain/hakusan/checkpoint_reference.py`
- `selftrain/hakusan/fork_resume_checkpoint.py`
- 对应两份测试文件

## 3.4 把 full 拆成可审查的 pilot4 → full 状态机

保留 `full.yaml` 的 40 轮总上限，但新增受控阶段：

```text
RUN_PHASE=pilot4  -> 本次 Trainer 只到 4 轮
RUN_PHASE=full    -> 只能从已审查的 pilot checkpoint resume
```

Pilot 正常结束后写：

```text
PILOT4_COMPLETE.json
pilot4-final.ckpt
```

而不是误写最终 `COMPLETE`。首次 full continuation 必须精确使用该 pilot checkpoint 的 basename、SHA 和 step 6944。

新增的 `FULL_STARTED.json` 防止后续从低于 pilot 边界的 rolling checkpoint 静默回退。

涉及：

- `src/spatialtrain.py`
- `selftrain/hakusan/run_training.sbatch`
- `selftrain/hakusan/submit_training.sh`
- `selftrain/scripts/finalize_training_phase.py`
- `selftrain/scripts/full_started.py`

## 3.5 实现正式 cue-control 独立 release checker

新增 checker 不只相信 `summary_full.json`，而是要求：

- `results_full.csv` 恰有 trial ID 0--9999 各一次；
- 四种条件的 correctness 都是 0/1；
- 从逐 trial CSV 重算四条件 accuracy；
- 重算 correct-vs-shuffled/silent point delta；
- 使用冻结 seed `20260816` 和 2,000 repetitions 重算 target-speaker cluster bootstrap CI；
- primary 至少 5 个百分点且两个 CI 下界均大于 0；
- summary、CSV、manifest、checkpoint、config、eval-code hash 全部一致；
- 拒绝 smoke、截断 CSV、NaN 和 Infinity。

提交端和计算节点分配 GPU 后都会再次验证 release，防止排队期间文件被替换。

涉及：

- `selftrain/scripts/check_cue_control_release.py`
- `selftrain/scripts/test_cue_control_release.py`

## 3.6 在训练前冻结 full-pilot 的 10k 评价 bank

新增 prediction-independent bank：

```text
9,000 mixed scenes
  = 4 个 distractor counts × 5 个 SNR bins × 每格 450
1,000 clean/cue-free scenes
总计 10,000
```

每个 cell 做 target gender 平衡；固定 target、distractors、cue、paths、crop centers、SNR、seed 和 SHA。另有 2,000 个平衡 cue-control subset。

Bank 必须在 pilot 模型构造和第一个 optimizer step 之前生成并写入 `PILOT4_BANK_FROZEN.json`。训练后 evaluator 只能验证和读取，不能重新抽样。

涉及：

- `selftrain/scripts/build_full_pilot_eval_bank.py`
- `selftrain/hakusan/run_training.sbatch`

## 3.7 实现 stage-0 vs pilot4-final 的逐 trial evaluator

新 evaluator 在完全相同的冻结 scene 上比较：

- stage-0 checkpoint；
- pilot4-final checkpoint。

它输出逐 trial 预测、NLL、概率与分层字段，并计算：

- overall 与 mixed accuracy/CE 的配对改善；
- clean accuracy；
- distractor count、SNR 和交叉 cell 指标；
- correct/shuffled/silent/distractor cue 对照；
- target-speaker cluster bootstrap CI；
- same/different-gender shuffled cue 敏感性（非门禁指标）。

scene mixer 会检查实测 SNR 与目标误差小于 `1e-4 dB`，所有结果必须有限。

涉及：

- `selftrain/scripts/eval_full_pilot.py`
- `selftrain/hakusan/run_full_pilot_eval.sbatch`
- `selftrain/scripts/test_full_pilot_eval.py`

## 3.8 实现 pilot release 的证据绑定

`pilot_release.py` 不接受仅手写几个数字的 `PILOT4_EVAL.json`。它会重新读取并验证：

- 冻结 10k bank 与 sidecars；
- per-trial results；
- frozen evaluator；
- config/source manifest；
- stage-0 与 pilot checkpoint；
- bank-freeze state；
- 人工 review 文件。

然后从逐 trial 数据独立重算全部固定门槛。只有 recomputed decision 为 `GO` 才能生成 `PILOT4_GO.json`，之后每次 full resume 都会重新走同一验证链。

涉及：

- `selftrain/scripts/pilot_release.py`
- `selftrain/scripts/test_pilot_release.py`

## 3.9 同步上传与 provenance 清单

更新 `upload.sh` 和 `run_integrity.py`，将新增的 checker、bank builder、evaluator、runner 和测试纳入：
