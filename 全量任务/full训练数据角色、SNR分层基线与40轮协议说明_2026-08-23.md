## 3. 约 43% 说明了什么

### 3.1 呈现平台迹象与早期过拟合预警

最近六轮为：

| epoch | train accuracy | validation accuracy | train loss | validation loss |
|---:|---:|---:|---:|---:|
| 15 | 68.6% | 43.0% | 1.55 | 2.84 |
| 16 | 69.6% | 42.6% | 1.49 | 2.84 |
| 17 | 70.6% | 43.0% | 1.44 | 2.85 |
| 18 | 71.8% | 43.3% | 1.38 | 2.83 |
| 19 | 72.7% | 43.5% | 1.33 | 2.85 |
| 20 | 73.4% | 42.4% | 1.29 | 2.86 |

可确认的事实是：

- `epoch 15--20` 的 validation accuracy 位于 `42.4%--43.5%` 的窄区间；
- 当前最佳 validation accuracy 是 `epoch 19` 的 `43.5%`；
- 当前最佳 validation loss 是 `epoch 18` 的 `2.83`；
- 同期 train accuracy 从 `68.6%` 升至 `73.4%`；
- train--validation accuracy gap 从 `epoch 17` 的 `27.6` 个百分点扩大到 `epoch 20` 的 `31.0` 个百分点；
- train--validation loss gap 从 `1.41` 扩大到 `1.57`。

因此可以说：

> 内部 validation 呈现近似平台迹象，且 train--validation gap 扩大，早期过拟合风险正在增强。

但现在还不能说：

- 模型已经确认过拟合；
- 43% 是理论上限；
- 模型已经完全收敛；
- `epoch 20` 显著差于 `epoch 19`；
- 后续训练一定没有收益。

原因是明显的 accuracy 下跌目前主要来自 `epoch 20` 一个点，validation loss 连续恶化也只有两轮，且没有逐 trial 配对置信区间。单轮波动不足以证明过拟合。

### 3.2 为什么 43% 不等于所有条件都是 43%

内置 `val_acc` 是 aggregate 指标，混合了：

- 1--4 名干扰者；
- 连续 `−10` 至 `+10 dB` 的 SNR；
- 约 10% 的 `cue_free` 分支，在当前实现中为 target-only/clean；
- 不同 target speakers、words 和 genders。

因此总体 43% 可能来自：

- clean 和高 SNR 条件表现很高；
- 低 SNR 条件仍然很低；
- 多干扰条件比单干扰条件明显困难。

一个 aggregate 均值不能反推出各个分层的准确率。43% 也不构成已知的人类上限、Bayes 上限或任务理论上限。

## 4. Training、validation、冻结 bank 与 final test

| 数据角色 | 定义 | 是否参与开发决策 | 合法用途 | 不应称为 |
|---|---|---:|---|---|
| 在线 training | 每轮按冻结采样规则在线生成的 full-distribution scenes | 是 | 更新模型参数、报告 train curve | 固定 test set |
| 内部 validation | 每轮运行的 aggregate validation，因满 batch 向上取整为 10,016 条 | 是 | 监控学习、平台、过拟合和选择 checkpoint | 最终独立 test |
| 冻结 10k pilot bank | 训练前固定的 10,000 个评估场景，已用于四轮 GO | 是 | 可重复 audit、SNR 分层、same-bank 配对比较 | 从未查看的最终 test |
| 最终独立 test | checkpoint 确定前从未用于调参、停止或模型选择，且数据单位与 train/validation 隔离 | 否 | 最终 primary 性能，只运行一次 | validation/gating bank |

强意义的独立 final test 应来自预先隔离、未参与 training、内部 validation 或 pilot GO 的 test anchors，并且与现有 pilot bank 不重叠；至少应在 speaker 和 recording 层面与 train/validation 分离。仅从当前 `validation_anchor_manifest` 中重新抽取并组合一套新场景，即使生成了新的 bank 和 hash，也仍只能称为新冻结的 validation/evaluation bank，不能称为严格独立 test。如果现实条件只能做到 scene-level 不重叠、无法做到 speaker-level 隔离，则必须准确称为“独立 scene-level holdout”，不能暗示完全 speaker-independent。

可以用考试类比：

```text
training   = 练习题
validation = 反复进行的模拟考试
final test = 模型锁定后才拆封的正式考试
```

Validation 不是“还没训练好的测试集”。数据的身份由用途决定，而不是由模型是否训练完决定。即使训练结束，已经被反复查看并用于决策的数据仍然是 validation，不会自动变成独立 test。

当前约 43% 应写成：

> 截至相应 epoch 的内部 validation top-1 accuracy。

不应写成：

> 模型在完全独立、从未用于任何训练决策的最终 test 上达到 43%。

## 5. 冻结 10k bank 是什么

`bank` 可以理解为“固定的评估题库”。它不是模型参数，也不是 10,000 个预先导出的 WAV 文件；它是一张逐行记录场景构造配方的 TSV manifest。

当前 bank：

```text
path:
selftrain/experiments/runs/fullpilot4_accum9_20260815_181000/
evaluation/pilot4/frozen_bank.tsv

SHA256:
d03404f2bca5aeb8a5d096b84f6ef758b6b07d0ee5efbd44ded59135bced0091
```

所有行都固定 target、correct-cue 候选、相关音频路径与 crop centre、speaker、word、label、target gender、trial ID 和 bank seed。不同类型的行还有不同字段：

- 9,000 个 mixed 行固定 1--4 名 distractors、具体 SNR 和 SNR bin；
- 1,000 个 clean 行为 0 distractor、SNR 为空，evaluator 使用 target-only scene 并将 cue 置零；
- 只有预先指定的 2,000 个 control 行具有完整的 shuffled/probe cue-control donor 配置。

例如一行可以理解为：

```text
trial 123
target speaker A 说 apple
correct cue = speaker A 的另一段、不同词录音
distractors = speakers B、C
SNR = -7.2 dB
SNR bin = [-10, -6) dB
correct label = apple
```

Bank 的固定结构为：

```text
total scenes       = 10,000
mixed scenes       = 9,000
clean scenes       = 1,000
distractor counts  = 1, 2, 3, 4
SNR bins           = 5
joint cells        = 4 × 5 = 20
mixed per cell     = 450
mixed per SNR bin  = 1,800
cue-control subset = 2,000
```

五档 SNR：

```text
[-10, -6), [-6, -2), [-2, +2), [+2, +6), [+6, +10) dB
```

多名 distractors 先按 equal-RMS 规则组成一个 combined background，再整体缩放到指定 SNR。定义为：

```text
SNR = 20 log10(target RMS / combined-background RMS)
```

正 SNR 表示 target 相对于合并后的 background 更强。

“冻结”表示每类 trial 所需的 paths、crops、SNR、distractors、适用的 cue donors 和 hash 已固定，不能根据模型输出重新挑题。让多个 checkpoints 回答同一个 bank，相当于让多个学生完成完全相同的考试，因此可以逐 trial 公平比较。

## 6. 为什么旧的 41%--43% 不能直接按 SNR 拆分

内置 validation 的 `metrics.csv` 含 batch/epoch 级聚合 scalar，但没有能与预测逐条连接的 trial ID，也没有保存每条 trial 的：

- 实际 SNR；
- prediction；
- distractor count；
- target speaker；
- 正确/错误标志。

实际 SNR 又是在在线音频变换阶段随机抽取，没有随结果落盘。因此现在只有一个总平均，无法从一个数值恢复五个未知的 SNR 分段数值。

正确方法不是重新训练，而是：

1. 锁定一个完整 epoch checkpoint；
2. 让该 checkpoint 对冻结 10k bank 做一次只读推理；
3. 保存 10,000 行逐 trial 结果；
4. 按 `snr_bin` 和 `distractor_count` 分组；
5. 计算每档 accuracy、cross-entropy 和配对置信区间。

这是重新“考试”，不是重新“学习”：不做反向传播，不更新模型权重，通常只需推理时间而不需要数天训练。

## 8. 是否需要作者 checkpoint 对照

### 8.1 旧的“作者约 45%”不能与当前 43%直接比较

需要纠正两个常见混淆：

- `45.8566%` 是自训 Job 551219 在“1 名 distractor、0 dB、always-correct cue、20 轮”条件下的 validation accuracy，不是作者 checkpoint；
- 作者历史结果中的约 45% 也只对应特定 cell，例如同 gender 单干扰 `−3 dB` 为 `46.2%`，或不同 gender 单干扰 `−9 dB` 为 `44.4%`，不是作者总体 accuracy。

作者 checkpoint 在旧 Common Voice 单干扰评估中的结果随条件明显变化：

| 条件 | −9 dB | −6 dB | −3 dB | 0 dB | +3 dB | clean |
|---|---:|---:|---:|---:|---:|---:|
| 同 gender distractor | 26.0% | 34.6% | 46.2% | 55.4% | 63.3% | 88.0% |
| 不同 gender distractor | 44.4% | 53.1% | 60.1% | 68.5% | 72.5% | 88.1% |

因此不能用“作者约 45%、我们约 43%”得出两者已经接近的结论。

### 8.2 Same-bank 作者对照有意义，但不是必须超过的门槛

合理的后续实验是让：

1. 我们预先锁定的 current/final checkpoint；
2. 作者公开 checkpoint；

回答完全相同的冻结 10k bank，并使用相同的冻结原始 scene waveform、cue、label 和评分规则。各 checkpoint 的主分析使用其绑定的原生 config/preprocessing，并明确报告差异；当前 `full.yaml` 启用了逐样本 leveling，而作者原配置没有启用该项，所以主分析是 system-level external comparison，不能解释成只隔离了权重差异。如果要强制统一 preprocessing，应另列为 sensitivity analysis，不能静默替代原生配置主分析。

主要输出应为：

- overall、mixed 和 clean accuracy/cross-entropy；
- 五档 SNR；
- 1--4 名 distractors；
- 20 个 `distractor count × SNR` cells；
- target gender；
- current 与 author 的逐 trial 配对差异；
- 按 target speaker 聚类 bootstrap 的 95% CI；
- 可选的 correct/shuffled/silent cue-control 比较。

这项比较的意义不是要求我们的模型必须击败作者，而是回答：

- 作者模型能否迁移到当前更困难的 full 评估任务；
- 两模型在低 SNR 和多干扰下谁下降更快；
- 两模型是否都依赖正确 cue；
- 当前从随机初始化训练的模型与公开模型之间还有多大差距。

当两个模型回答相同 bank 时，评估难度对两者相同，因此比较有意义。即使我们的模型更低，也不等于训练失败，因为作者和当前模型的训练数据、训练预算、增强方式和训练分布并不匹配。

作者 checkpoint 应称为：

> external/reference same-bank baseline

不应称为：

> 训练预算和数据严格匹配的公平消融。

此外，当前归档材料中没有可核验的逐条作者训练 manifest，因此无法排除作者训练数据与当前 Common Voice speakers/recordings 的重叠。该比较不能单独证明无泄漏的外部泛化排名。

## 9. 是否可以在当前分段后提前停止

### 9.1 科学判断

过拟合不等于本次训练无意义。即使后续出现“train 继续提高而 validation 持续下降”，此前 checkpoint、学习曲线、cue-control 和 SNR 分层结果仍然有效，可以在内部 validation 上提出候选训练预算，并定位开发集开始劣化的区间。若据此选择 checkpoint，必须明确其模型选择性质，并在未参与选择的独立 test 上确认，不能把事后 validation-best 直接称为无偏最佳训练预算。

截至 `epoch 20`，更准确的结论是：

> 已呈现 validation 平台迹象与早期过拟合预警，但尚未通过多轮持续恶化确认过拟合。

因此当前不建议中途取消 Job 614647。应让这个四天分段自然结束，再依据完整 `sacct`、日志和完整 epoch checkpoint 审查。

### 9.2 原冻结协议的边界

冻结 `full.yaml` 明确设置：

```text
epochs = 40
early stopping = disabled
expected final global_step = 69,440
```

现有 pipeline 只有完成 40 个 epoch 才会发布：

```text
full/checkpoints/formal-final.ckpt
state/COMPLETE
```

因此，如果当前分段结束后不再续交：

- 工程上可以保留最近完整 epoch checkpoint；
- 已得到的训练与验证证据不会消失；
- 但该 run 必须标记为 manual early stop / planned-40-epoch protocol deviation；
- 不能手写 `state/COMPLETE`；
- 不能把中途 checkpoint 改名冒充 `formal-final.ckpt`；
- 不能称为“完成了 40 轮 full 实验”。

### 9.3 当前推荐

对正式发表和最小选择偏差，当前推荐仍是：

1. 让 Slurm segments 只由 walltime 决定；
2. 每段从 `global_step` 最大的完整 epoch checkpoint 恢复；
3. 完成原定 40 个 epoch；
4. primary checkpoint 固定为第 40 轮；
5. 中间 validation-best checkpoint 只作清楚标注的 secondary 分析；
6. 模型和 checkpoint 锁定后，再运行一次最终独立 test。

如果计算预算确实要求提前结束，则应创建时间戳化的 post-hoc protocol amendment，明确：原计划是 40 轮、修改时已经看过 `epoch 0--20`、终点 K、停止理由、checkpoint 选择规则，以及该决定不是原始预注册。

## 10. 现有 10k bank 不是最终未触碰 test

冻结 10k bank 已经在 Job 584990 中用于判断四轮 pilot 是否获得 `GO`，因此它已经参与开发决策。它仍然非常适合：

- 固定、可重复的 paired audit；
- current 与 author checkpoint 的 same-bank 比较；
- SNR、干扰者数量和 gender 分层；
- cue 机制验证。

但它不再是完全 untouched 的最终 test。如果在多个 epoch 上反复运行该 bank，并根据结果选择停止时间或 checkpoint，选择偏差会进一步增加。

最严谨的发表结构是：

```text
training data
    用于梯度优化

internal validation
    用于学习曲线、平台与checkpoint开发

frozen 10k pilot/audit bank
    用于固定机制审计和same-bank参考比较

independent final test bank
    在最终checkpoint锁定后只运行一次
```

如果最终没有建立独立 test bank，则应把最终数字准确称为 validation/evaluation-bank performance，而不是 independent test performance。
