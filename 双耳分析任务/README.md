## 0. 一句话目标

用作者预训练的 checkpoint,做**双耳分听(dichotic listening,両耳分離聴)**任务:
左右耳分别输入**同一说话人**的不同语音,cue 只给目标耳,让模型报出**目标耳的中间词**。
对标人类(成人在该任务上正确率接近 100%),看模型能否达到足够高的正确率。

**这是导师第 1 个任务。第 2 个任务(调研自己训练模型的可行性)不在本文件夹范围。**

---

## 1. 任务从哪来(会议结论)

2026-07-21 月度会议(录音 `新录音 12.m4a`)确定:diotic 的 Fig 2a 复现已完成,下一步做双耳分听。
导师明确的设计要点:

- 左右耳**同一个说话人**在说话(和人类实验对齐,是较难、也是关键的条件)。
- cue 指示"注意哪只耳":cue 放目标耳,另一只耳静音。
- 同一对刺激左右互换各测一次,消除左右偏。
- 判据从简:**成人接近 100%,所以模型也应接近 100% 才算合格**;若只比随机(0.5)高一点(如 0.6)就有问题。
- 不必做更严格的逐项妥当性验证,确认绝对值够高就进入下一步。
- (背景)人类有**右耳优势**(单词识别右耳更准,因语言区在左脑);模型没有语言区,大概率不会出现,但应记录左右耳差异以备汇报。

## 2. 方案与既有 diotic 管线的区别

| 环节 | 既有 diotic(任务 A~D,已完成) | 双耳分听(本任务) |
|---|---|---|
| 通道构造 | `DuplicateChannel`:单声道复制成左右**相同** | 左耳=target,右耳=distractor,**各占一声道、不相加** |
| cue | 双耳相同 | 只给目标耳,另一耳**静音** |
| 说话人 | distractor 是**不同**说话人 | 左右耳**同一**说话人(不同录音、不同中间词) |
| SNR | 6 档 SNR 扫描 | **不扫 SNR**,左右耳等强度(无 ILD,耳机呈现) |
| 归一化 | 单声道 RMS 0.02 后复制 | 左右语音各自RMS 0.02；单耳cue按双耳全局RMS 0.02 |
| 评分 | 中间词识别准确率 vs SNR | 命中率(报被 cue 耳的词)+ 耳混淆率 + 左右耳差异 |

模型本身是双通道架构(`input_channels=2`),双耳分听在架构上原生支持。

## 3. 第一步:可行性验证(已完成 ✓)

### 3.1 为什么先做这一步

会议上"单耳呈现 cue 能否指定目标耳"只是**推定,没人实测过**。如果这个前提不成立,
建整个数据集就是白费。所以先用小样本验证:**cue 放哪只耳,模型是否就报哪只耳的词。**

### 3.2 机制预期(读 `SimpleAttentionalGain` 后)

gain 逐通道计算:cue 只在目标耳有能量 → 该耳按频率选择性放行;另一只耳 cue 近似静音
→ gain 被压到 floor(bias θ1),即被抑制。所以理论上应当路由到 cue 所在的耳。用实测确认。

### 3.3 两个探针脚本

1. **`scripts/dichotic_probe.py`** —— demo 音频解耦测试(男/女不同说话人)。
   固定混音「左耳=男声 about,右耳=女声 above」,只用同一个 cue、改变放哪只耳,
   看模型跟随"耳朵位置"还是"说话人身份"。
   **结论:有信息但被混淆。** 冲突行之一(男 cue 放右耳)干净地跟随了耳朵→报 above;
   另一条(女 cue 放左耳)报出无关词 `football`。原因是该测试人为制造了
   "cue 说话人 ≠ 目标耳内容说话人"的组合,gain 谱不匹配产生伪影——**真实任务(同说话人)
   不存在此混淆**,所以这个乱词是对抗性测试的人为产物,不代表真实条件。

2. **`scripts/dichotic_probe_samespeaker.py`** —— 同说话人决定性测试(**真实条件**)。
   左右耳都是同一个人(不同录音、不同中间词),cue 也是这个人的第三条录音。
   说话人处处相同 → cue 唯一能区分的就是**耳朵位置**,彻底消除上面的混淆。

### 3.4 初步结果(20 说话人 / 80 trials)

见 `results/samespeaker_probe_20spk.txt`:

| 指标 | 结果 | 含义 |
|---|---|---|
| **命中**(报被 cue 那只耳的词) | **72.5%** | 95% Wilson CI约61.9%–81.1% |
| **耳混淆**(报成对侧耳的词) | **0.0%** | 关键:模型从不报错耳的词 |
| 其他(两耳词都不是) | 27.5% | 可能包含基线识别错误和双耳竞争损失 |
| 左耳 75% / 右耳 70% | — | 无明显耳偏 |

**核心发现:耳混淆 0.0%。** 80次试验中，模型58次回答了两耳呈现词之一，这58次全部
选择了cue耳的词；条件路由正确率为58/58，95% Wilson CI约93.8%–100%。这为“单耳cue
能够路由目标耳”提供了较强的初步证据。

但72.5%的总命中率仍明显低于会议中提出的“成人接近100%”参照，不能把任务1直接判定为
完成。旧探针没有对同一刺激测量单耳和diotic clean基线，因此也不能断言27.5%的其他回答
全部只是词本身识别失败。另外，旧结果文件生成时，单耳cue的活动通道RMS设为0.02，导致
双耳全局RMS只有0.014；正式脚本已按作者双耳预处理规则修正为全局RMS 0.02。

### 3.5 结论

**双耳分听方案可以进入正式评估，但任务1尚未完成。** 当前证据支持路由可行；是否达到
足够高的绝对识别率，需要在严格清单和匹配基线上完成正式评估后判断。

## 4. 正式建集与评估（已完成 ✓）

沿用既有 diotic 管线的四步结构,只改配对规则与刺激构造:

- **A. 同说话人配对**：左右target取自同一`client_id`的两条不同录音，锚点词不同且都在
  800词表；cue必须是该说话人的第三条录音，且cue句子不包含左右目标词。
- **B. 切词**:复用现有 forced alignment 产物,以中间词为中心切 2.5s 取中 2s。
- **C. 构造刺激**：左右耳语音各自RMS 0.02，分别占一个通道，不相加、不扫SNR；单耳cue
  按双耳全局RMS 0.02归一化，左右分配互换各测一次。
- **D. 三种条件同时评估**：
  1. 双耳分听：主结果；
  2. 同耳单声源、目标活动耳RMS匹配：检查单耳零通道输入（不作为识别上限）；
  3. 标准diotic clean：确认该词在既有预处理下是否本来就能识别。

原README所写“136名满足条件”实际只统计了至少两个锚点的说话人，没有同时要求两条独立
target录音和第三条cue录音。重新严格核查后：

- 119名说话人有两条不同target录音和不同目标词；
- 从Common Voice `validated.tsv`另选第三条独立cue后，110名满足全部条件；
- 每人4个trial，共440个正式trial；
- 选择按路径和词的固定顺序完成，不使用任何模型预测，因此没有按结果筛刺激。

正式清单已经生成在`data/dichotic_manifest.csv`。8条端到端smoke结果为双耳命中8/8、
同耳单声源8/8、diotic clean 8/8；这只证明管线正确，样本太小，不能当正式结果。

### 4.1 正式结果（110说话人 / 440 trials）

| 指标 | 结果 | 95% Wilson CI |
|---|---:|---:|
| 双耳精确命中 | **347/440 = 78.9%** | 74.8%–82.4% |
| 报成对侧耳的词 | **0/440 = 0.0%** | 上限0.9% |
| 其他词 | 93/440 = 21.1% | 17.6%–25.2% |
| 在回答了两耳呈现词之一时的路由正确率 | **347/347 = 100%** | 下限98.9% |
| 单耳零通道控制 | 311/440 = 70.7% | 66.3%–74.7% |
| 标准diotic clean | 392/440 = 89.1% | 85.8%–91.7% |

表中是逐trial Wilson区间。因每名说话人贡献4个trial，另外按110名说话人做了20,000次
聚类bootstrap：双耳命中率的95%区间为73.4%–84.1%，结论不变。

在diotic clean本来能识别的392条中，双耳条件命中339条（86.5%）。配对结果为：
两条件都对339、仅双耳对8、仅diotic clean对53、都错40。因此，绝对正答率不高既包含
这批Common Voice切片的基线识别错误，也包含额外的双耳竞争损失。

左耳与右耳命中率为79.5%和78.2%。对220个相同目标做左右配对后，仅左耳对10个、
仅右耳对7个，未见明显的模型耳侧优势。

### 4.2 任务1的正式判定

**刺激管线与耳路由验证已完成，但模型未达到会议设定的“成人接近100%”绝对正答率标准。**
这是可报告的负结果，不应为追求100%而根据模型预测筛掉难刺激。同时，本结果使用的是
自建Common Voice刺激和公开的单个checkpoint，不能直接解释为与人类实验的严格数值对比。
详细说明见`docs/正式评估结果_2026-07-21.md`。

### 4.3 错误与中央2秒声学审查（自动部分已完成）

`scripts/audit_dichotic_errors.py`对440条trial按模型实际使用的中央2秒重新计算RMS、
低能量帧比例、目标耳与对侧耳的有效电平差、标签字符串近似度和说话人错误聚集。

- 93个错误中：基线与双耳共同错40，双耳特异错53，对侧耳混淆0；
- 13/93个错误的目标词与预测词字符串相似度≥0.8；
- 25/40个基线错误在diotic与双耳条件重复了同一个错词；
- 中央2秒目标耳减对侧耳的有效电平差中位数为0.00 dB，中央95%范围为-1.79到+1.79 dB；
- 有方向电平差与命中无明显关系（Spearman ρ=0.042，p=0.385）；
- cue低能量帧比例与说话人错误数无明显关系（ρ=0.074，p=0.444）。

因此，当前没有证据表明静音或目标耳整体更小声是78.9%的主要原因。
`results/dichotic_manual_review.csv`已按优先级排好93条人工听音任务；人工栏保持空白，
需要听者判断目标词可听度、对齐、转录、音质和标签等价性。

## 5. 怎么运行

在仓库根目录、conda 环境 `audattn` 下:

```bash
cd ~/projects/auditory_attention
conda activate audattn

# demo解耦探针（教学/机制检查）
python 双耳分析任务/scripts/dichotic_probe.py

# 旧同说话人探针
python 双耳分析任务/scripts/dichotic_probe_samespeaker.py --speakers 20

# 重建严格正式清单
python 双耳分析任务/scripts/build_dichotic_manifest.py

# 小样本端到端检查
python 双耳分析任务/scripts/run_dichotic_eval.py \
  --limit 8 --out 双耳分析任务/results/dichotic_smoke_8.csv

# 完整正式评估；支持中断后继续。CPU自动batch=1，CUDA自动batch=4
python 双耳分析任务/scripts/run_dichotic_eval.py --resume

# 汇总、95%区间和结果图
python 双耳分析任务/scripts/analyze_dichotic_results.py

# 中央2秒声学审查和93条人工复核表
python 双耳分析任务/scripts/audit_dichotic_errors.py

# 导出第1–10条的本地听音WAV（WAV不进入git）
python 双耳分析任务/scripts/export_dichotic_review_audio.py \
  --start 1 --limit 10

# 导出全93条并生成本地浏览器复核页面
python 双耳分析任务/scripts/export_dichotic_review_audio.py --all
python 双耳分析任务/scripts/make_dichotic_review_page.py
```

CPU上8条三条件评估约需数分钟，完整440条适合在GPU运行。本地运行会每条保存并支持
`--resume`，即使中断也不必从头开始。不要在CPU上把batch调大；耳蜗前端中间张量会占用
大量内存。
