# 同说话人双耳分听模型评估（2026-07-22）

## 项目信息

- **项目名称**：同说话人双耳分听模型评估
- **英文名称**：Same-speaker Dichotic Listening Model Evaluation
- **整理日期**：2026-07-22
- **仓库目录**：`auditory_attention/双耳分析任务/`
- **使用模型**：作者公开的feature-gain预训练checkpoint
- **checkpoint**：`epoch=1-step=24679-v1.ckpt`

## 1. 研究目的

检查预训练听觉注意模型能否完成同说话人双耳分听任务：

1. 左右耳同时呈现同一说话人的不同句子和不同目标词；
2. cue只呈现在目标耳，对侧耳的cue通道为零；
3. 评估模型是否输出cue耳的中心词；
4. 分开评价“耳朵选择是否正确”和“单词绝对识别是否正确”。

会议中设定的参考标准是：成人在类似的同说话人双耳分听任务中接近100%；如果模型仅有60%左右，
则不足以说明该模型已达到成人水平。

## 2. 实验过程

### 阶段1：设计审查

- 阅读模型的双通道输入和`SimpleAttentionalGain`实现。
- 确认模型可接收两耳不同的刺激，并通过单耳cue对目标耳进行增益。
- 将任务定义为：左右耳为同一说话人，但来自不同录音、不同目标词。
- 设计左右互换（AB/BA）和cue耳互换，避免耳侧与特定词绑定。

设计审查详见`docs/设计审查_2026-07-21.md`。

### 阶段2：小样本机制探针

- 先用不同说话人的demo音频检查cue的耳路由机制。
- 由于说话人身份与cue耳产生冲突，该对抗性测试出现了无关词。
- 改用真实任务所需的同说话人刺激后，在20名说话人、80个trial上得到：
  - 精确命中58/80（72.5%）；
  - 对侧耳混淆0/80；
  - 在模型回答了两耳呈现词之一时，路由正确58/58。

该阶段证明方案可行，但由于样本较小且没有匹配基线，不能将72.5%作为最终结果。

### 阶段3：严格刺激清单

从Common Voice中按如下条件建立清单：

- 每名说话人必须有两条独立target录音；
- 两个target的中心词不同，且都在800词分类词表中；
- cue必须来自同一说话人的第三条独立录音；
- cue句子不包含左右目标词；
- 不使用任何模型预测结果筛选刺激。

严格核查后，110名说话人满足条件。每名说话人生成4个trial，共440个trial。
清单和审计信息位于`data/dichotic_manifest.csv`和`data/dichotic_manifest.audit.json`。

### 阶段4：端到端smoke test

对新管线的前8条运行三种条件：

1. 同说话人双耳分听；
2. 目标耳RMS匹配的单耳零通道控制；
3. 标准diotic clean控制。

8条smoke test的三种条件均为8/8，证明音频切片、双通道构造、模型推理和评分流程可正常运行。
该结果仅是工程检查，不是正式结果。

### 阶段5：440条正式评估

- 使用CPU运行全部440条，每条同时计算三种条件。
- 推理脚本按trial写入CSV，支持`--resume`断点续跑。
- 使用当前说话人对的耳蜗图缓存，避免重复计算并控制CPU内存。
- 440个trial ID全部唯一，全440条的状态都为`ok`；左右cue耳各220，AB/BA各220。

### 阶段6：统计、绘图与错误分层

- 计算精确命中、对侧耳混淆、其他词、左右耳差异和两个控制条件。
- 提供逐trial Wilson 95%区间。
- 因每名说话人贡献4条相关trial，另按110名说话人做20,000次聚类bootstrap。
- 将93个双耳错误自动分为40个“基线和双耳都错”与53个“仅双耳错”。

## 3. 正式结果

| 指标 | 结果 | 区间/说明 |
|---|---:|---|
| 双耳精确命中 | **347/440 = 78.9%** | 说话人bootstrap 95%区间73.4%–84.1% |
| 对侧耳词 | **0/440 = 0.0%** | 逐trial Wilson上限0.9% |
| 其他词 | 93/440 = 21.1% | 不是两耳呈现词中的任何一个 |
| 条件耳路由 | **347/347 = 100%** | 逐trial Wilson下限98.9% |
| 单耳零通道控制 | 311/440 = 70.7% | 说话人bootstrap 64.8%–76.4% |
| 标准diotic clean | 392/440 = 89.1% | 说话人bootstrap 85.0%–93.2% |

在392条diotic clean可正确识别的trial中，双耳条件命中339条（86.5%）。配对列联表为：

- 双耳与diotic clean都正确：339；
- 仅双耳正确：8；
- 仅diotic clean正确：53；
- 两者都错：40。

左耳命中为175/220（79.5%），右耳为172/220（78.2%）。对220个相同目标进行左右配对后，
两耳都对165、仅左耳对10、仅右耳对7、两耳都错38，没有明显耳侧优势。

## 4. 如何解释

### 可以确认的事情

- cue指定耳的路由机制很稳定：440条中没有一次报成对侧耳的目标词。
- 初步探针的72.5%并非偶然代码故障；严格正式清单的78.9%与其方向一致。
- 识别失败同时包含基线单词失败和双耳竞争的额外损失。

### 不能过度声称的事情

- 78.9%没有达到会议设定的“成人接近100%”标准。
- 本实验使用自建Common Voice刺激，人类数据与模型数据不是同一组刺激，因此不能将数字直接相减并宣称严格人机差异。
- 实验使用一个公开checkpoint，而论文中的部分数字来自多模型汇总。
- 单耳零通道条件偏离模型训练时的双耳输入分布，因此不能把70.7%当作理论识别上限。

## 5. 正式结论

> 同说话人双耳分听的刺激生成、模型推理和评分管线已经完成。结果支持cue能稳定选择目标耳，
> 但不支持当前模型在该Common Voice刺激上已达到成人接近100%的绝对单词识别率。

这是完整且可报告的结果，不应根据模型预测筛除难刺激来人为提高主结果。

## 6. 错误审查与下一步

`results/dichotic_error_audit.csv`已将93个错误分为：

- `baseline_and_dichotic_error`：40个。优先检查强制对齐、切片中心、录音质量和静音比例。
- `dichotic_specific_error`：53个。检查目标/干扰词关系、cue匹配和模型置信度。

审查时保留全部440个trial，将审查信息作为诊断标记，不重算删除难例后的“更好看”主结果。

完成错误审查后可进入下一阶段：

1. 如果目标是验证方案可行性，将“耳路由成功、绝对值未达标”作为任务1结论，转入自训练模型的可行性评估。
2. 如果必须与成人数值直接比较，需要先获得或重建与人类实验完全一致的刺激和评分条件。

## 7. 复现方法

在仓库根目录执行：

```bash
cd ~/projects/auditory_attention
conda activate audattn

# 重建严格清单
python 双耳分析任务/scripts/build_dichotic_manifest.py

# 运行全部正式评估，支持断点续跑
python 双耳分析任务/scripts/run_dichotic_eval.py --resume

# 重新生成统计、图和错误审查表
python 双耳分析任务/scripts/analyze_dichotic_results.py
```

Common Voice原始音频和checkpoint因体积与授权原因不放入本实验目录；脚本会从仓库和本地数据路径读取。
