# 编译模型登记候选：先验收一次受控 CPU 前向

这是独立候选，不覆盖 v18 或先前 eager-only 原型。目标是让同版本编译器、
预登记观测器与原推理检查共存；目前没有开放生产/CUDA 模式。

## 本次已完成

本地 PyTorch 2.12.1 的 16 项测试通过；相同源码被打包到全新临时目录，
在新 Python 进程中再次通过 16 项，零跳过。前一版准备接口的 18 项也重跑通过。

- 精确绑定 outer → OptimizedModule → _orig_mod 和各阶段模块。
- 复用原准备函数的两条登记调用插入，原 AST 还原校验保持。
- 单独的 CompiledLease 保留已有状态、输入、RNG、运行设置、事件顺序、
  hook 身份和落盘字节检查；不修改旧类的“拒绝编译模型”规则。
- 编译器仍必须通过原 v18 的 torch 2.1.1+cu118 / 源码 SHA / 冷启动检查。
  本地 2.12.1 只测试该入口正确拒绝，不冒充通过原编译器检查。
- 本地确实执行了一次合成 CNN 的 compiled eager-backend 内部调度，
  4 次阶段调用、4 个落盘记录；它不是原 worker/真实模型的前向验收。

## 下一条命令（Mac 终端）

```bash
cd "$HOME/发表/超算/docs/superpowers/evidence" &&
bash 2026-09-12-compiled-registration-cpu-check.sh
```

入口先检查连接脚本、驱动、15 份源文件的 SHA，再认证并立即执行一次探针。
密码只输入 SSH 的终端提示，不存入脚本或聊天。现无可复用 socket，
因此本轮没有实际执行远端探针。

远端将把源码放入独立的 /tmp 临时树，使用真实 torch 2.1.1+cu118，
在全新进程中创建合成模型，安装钩子，调用原编译器身份签发和原
trace_predict_batch，一次 batch=16 的前向后撤销身份并移除钩子。
使用 eager 编译后端，不是 Inductor；不加载 formal40 或其他 checkpoint。
CPU 子进程 60 秒、引导进程 80 秒、本地传输 90 秒上限。正常完成或受控
子进程超时后清理临时树；外部强杀/网络故障不能保证清理完成，未见清理
回执不得当作成功。没有自动重试，没有发布文件到生产目录，没有 Slurm 作业。

输出与 receipt 保存于 evidence/compiled-remote-cpu-*。无论成功或失败都返回
输出复核；不通过时保留原因，不放宽版本、源码、RNG 或推理检查。

## 仍未完成
