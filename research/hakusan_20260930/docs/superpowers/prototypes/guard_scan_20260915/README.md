# 模块扫描性能候选（非部署版本）

只改原v18的`_live_protected_module_bindings`函数。冻结v18和已发布GPU v4包均不修改。
`candidate.py`从SHA固定父文件构造内存中的测试副本，并用AST检查其他顶层定义完全不变。
该副本不由原版发行加载器授权；测试明确确认原BaselineBridge会拒绝将它当作原冻结v18。
不能直接把它上传覆盖旧代码，也不能用旧提交脚本启动它。

## 改动及不变项

旧实现先遍历全部模块名检查类型，再构造全集、差集，最后处理候选名。
候选在每次调用中仍新建实时名称快照，但在一个循环内完成类型检查、已有非保护名称筛选、
保护名称识别及当前绑定读取，避免临时全集和差集。

每个名称在哈希、相等比较、`partition`之前必须是精确`str`，不调用异常键的自定义方法。
保护名称的当前对象每次读取；新名称、删除、同名替换、保护根集合变化仍可见。
现有缓存仍只含已验证的非保护字符串名称，作用域仍为同一次检查的`_SealBudget`。
不缓存检查通过结果或绑定对象，不跳过任何推理前后检查，不减少扫描调用次数。
扫描结果为名称到对象的映射；内部遍历顺序改变，不构成并发原子性保证。
原加载器的前后两次扫描和函数/元数据逐项检查保持不变。

## 已完成的本地验证

- 28项：原18项扫描/绑定测试应用于候选，加10项候选测试。
- 新测试包含600步确定性随机注册表变更差分、热缓存同名字符串子类、
  同数量键替换、异常晚到名称、禁止将候选当原发行版、参数/hook/运行时读取器检查。
- 4个独立CPU进程以原/候选/候选/原顺序测量完整合成B2两轮，未开启cProfile。
- 另外2个独立进程用于cProfile计数；对应输出和边界记录一致，检查调用次数一致。
- 原始本地58份发布来源、候选4份Python源码和2份原测试来源前后SHA一致。

合成batch=1中位数：原10.482秒，候选7.979秒，耗时减少约23.9%。
单扫描微基准：2048键约1.81倍、8192键约2.13倍。均为本地CPU，不是实际A100速度。
