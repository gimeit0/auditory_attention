# v10：完整模型执行检查的累计工作量修复

目标保持三固定模型、同一 10k bank 的完整可复核比较。本项解决其前置诊断
工具阻塞，不把本地回归或 CPU 加载称为最终完成。

## 开工证据与约束

v9 临时真实 formal40 CPU 检查已严格加载全部参数、检查 67 模块状态及
9 个主要调用图。完整模型指纹在 conv_block_1.1 的标准 Module._call_impl
遍历触发 work=200001（上限200000）；unique callable nodes=121。
没有 GPU 推理或 v9 发布。本轮保留 v9 十三文件固定候选及两次失败探针。

先在独立 v10 机械更新目录/协议版本，再加入真实 PyTorch 重复模块结构的
失败回归。首选修复只缓存同一次有界检查中的不可变 code-object 字节码
分析，避免反复 disassemble/收费；缓存持有 code object 强引用，不能按
裸 id 跨检查复用。每次仍重新读取 globals、闭包、defaults、bound self、
属性、hook、模型配置和注册状态。工程工作/节点/深度上限保持不变，科学
canary、精度设置、矩阵、checkpoint、bank、角色不改变。

必须以真实结构测试证明降低了实际重复计算，而非仅停止计费。若这一最小
实现仍不足，不假称修好；根据计数再评审有界优化。不能缓存 live 指纹、
跳过子模块或直接提高 200000 上限。验证包括真实预算 RED→GREEN、跨次与
同次 live 变更、code 替换、缓存隔离、巨型/大量不同代码拒绝及旧全部回归。

本地通过后仍须实际 2.1.1/formal40 CPU 路径；之后才考虑受控部署和一次
32 条 GPU 诊断。此文件先记录实施边界，结果将在执行后追加。
